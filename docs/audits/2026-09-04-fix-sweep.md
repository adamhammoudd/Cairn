## ⚠️ Escalated — needs a decision, not shipped here

### E1. Should Cairn's AI assistant ever be given the user's real portfolio dollar figures?

Audit finding #1 has a fix half (shipped in PR #58) and a product half (this).

The chat context builder (`src/lib/ai/context.ts` `buildChatContext`) only ever fetches **symbol
strings** — which tickers a user holds/watches — never dollar value, day P/L, or cost basis. PR #58
removes the system-prompt example that was coaching the model to answer *as if* it had those
numbers, so the confabulation-coaching is gone now.

The open question the audit raised and I did **not** decide: should the assistant instead be
*given* real value / P&L / cost-basis so answers in that shape are actually grounded? That is a
data-exposure decision (personal financial data into an LLM prompt, sent to Groq for inference)
with a compliance dimension — it belongs with the founder / cfo-legal-advisor, not with a bug fix.
Until it's decided, the assistant stays ticker-symbol-only.

**Related deliberate behaviour change in PR #58:** to stop the scope guard auto-rejecting a
*neutral* factual sentence that merely mentions a holding (e.g. "your portfolio is up 1.24%
today"), `PERSONAL_POSSESSION` now only fires when the clause also carries a trade action, an
advice frame, or evaluative language ("overexposed", "too concentrated"). One prior regression
case (`"Your position in AAPL is up 12% since you bought it."` → previously MUST-FLAG) is now
MUST-PASS. This is correct for a *directive* guard, but it means a bare confabulated figure is no
longer stopped **here** — it's governed by the system-prompt rules, `checkNoFreelancedProbability`,
and ultimately E1. Flagging it so the change is visible, not buried.
