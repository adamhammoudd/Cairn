## 1. Stale portfolio prices (root cause) — FIXED (both halves) + one deeper issue found (E2)

**Root cause, confirmed against the live DB (read-only queries via the Supabase MCP, no writes):**
`symbol_directory`: 75 rows, 64 stale (`last_checked_at` > 24h) — matches the walkthrough exactly.
`ingest-market-data`'s main configured-provider loop (`supabase/functions/ingest-market-data/index.ts:109-132`)
wrote fresh bars to `historical_prices` every run but **never updated `symbol_directory`** — only
its separate on-demand pass did (line ~163-166 pre-fix). `ingest-crypto` never wrote to
`symbol_directory` **at all** (confirmed by `grep` — one read, zero writes, pre-fix). Live proof
this was really happening: equities' `historical_prices` were fresh as of `2026-09-03` (yesterday)
while their `symbol_directory.last_checked_at` sat wherever migration 0027's backfill or an
on-demand search last left it — the ingestion was working, the *health check reading it* wasn't.

**Fixed (a):** New `supabase/functions/_shared/symbol-directory.ts` (`buildDirectoryPatch`) — one
pure function deciding what a directory row should look like after an ingest attempt
(success/no-data/error), shared by both edge functions so they can't drift on the mapping. Wired
into `ingest-market-data`'s configured loop and `ingest-crypto`'s metrics pass (which touches every
tracked coin every run, unlike the 4-coin history budget — see E2). **Needs Adam to deploy both
functions — see E1.**

**Fixed (b):** `getLatestCloses()` (`src/lib/market-data/current-price.ts`) already attempted a live
quote before falling back to a stored close; I hardened two things:
- The crypto-quote hint now comes from the holding's own stored `asset_type` (ground truth the
  Edit-asset modal writes) via a new `assetTypeBySymbol` parameter, not inferred from
  `historical_prices` bars that can be missing, stale, or reordered — a symbol with no bars yet
  would previously get `hint = undefined` and could resolve to the wrong instrument entirely (the
  file's own comment: `BTC` the bare ticker is Grayscale's ETF at ~$34, not the coin).
- New `isStaleClose()` flags a fallen-back-to close as stale when it's older than a threshold —
  36h for crypto (trades every calendar day), 96h for equities/ETFs (long weekends are normal).
  Threaded through `computeHoldingMetrics` → `HoldingMetrics.priceStale`/`priceAsOf`, surfaced in
  `holdings-table.tsx` as a small ⚠ with a tooltip on the Price cell, both desktop and mobile.

**What I could not fully confirm live:** I traced the exact "why does Holdings show a wrong number"
mechanism as far as static analysis + real DB queries allow, and directly confirmed the Twelve Data
quote endpoint returns a correct live BTC price right now (`curl`, key redacted from any output).

**Also fixed, the no-cost-impact half of E2:** `ingest-crypto`'s history-refresh queue now

## 3. AI chat citation token leak — FIXED

**Root cause:** the chat system prompt tells the model to cite with a real `[label](url)` markdown
link, but the context block it's shown (`chat-generate.ts` `buildContextBlock`) JSON-dumped each
news item complete with its raw `id` (a UUID) and **no `url`** — nothing to build a link from. The
model fell back to citing by the one identifier it had, wrapped in its own default citation bracket
notation (`【id】`), which `lib/ai/markdown.ts`'s parser has no rule for, so it rendered as literal
text. Confirmed against the real stored message (`chat_messages.id = cf46b275-...`, see E3) — the
exact two UUIDs from the walkthrough are real `news_items.id` values from that turn's context.

**Fix, two parts:**
- `context.ts`: the chat's news query now selects `url` (it already existed on `news_items` — the
  ticker page's own query already selects it).
- `chat-generate.ts` `buildContextBlock`: neither `analyses` nor `news` shown to the model include
  their row `id` anymore (nothing downstream needs the model to echo it back — `analysisIds` for
  the attached card comes from `context.analyses` directly, never parsed out of the reply).
- New `lib/ai/citations.ts` `resolveCitations()`: a deterministic backstop, same discipline as the
  probability card (which never trusts the model to format its own source list — its "Sources · N"
  list is server-rendered from a DB join, not parsed from the model's prose). Any `【...】` marker
  that resolves against a source actually in this turn's context becomes a real markdown link
  (reusing the *already-correct* link renderer in `markdown-message.tsx` — not a new UI); anything
  else (hallucinated id, resolvable id with no url) is dropped rather than ever reaching the user.

**Test:** `npm run test:chat-citations` (12/12) — the exact reported failure (two UUID markers in
one reply) resolves to real links; unresolvable/no-url markers are dropped cleanly with no stray
punctuation/whitespace; real markdown links the model writes itself are left untouched.

**Verification against the live suite:** `test:ai-suite`'s Tier B (live model pipeline) ran 22 real
chat turns through the updated `chat-generate.ts` — 21 passed end-to-end (including several that
specifically exercise the scope guard); the one failure is the Cerebras fallback's pre-existing
HTTP 402 quota issue (documented in the 2026-09-03 audit), unrelated to this change.

## 4. Markets page tab/table desync — FIXED

**Root cause:** `TrendingDeck` (the "Day gainers / losers / Most active / Most searched" card row)
owned its selected tab as its own local `useState` — nothing connected that selection to
`MarketsPanel`'s table, which only ever sorted by asset-type tab + search query. Confirmed by
reading both components: `TickerList` renders `rows` in whatever order it receives with no sort of
its own, and `filtered` in `MarketsPanel` never referenced `TrendingDeck`'s `deck` state at all.

**Fix:** new `src/lib/market-decks.ts` — `DECKS`/`deckValue`/`deckComparator`/`deckHasSignal`, the
one shared definition of what each deck ranks by. `deck` state moved up to `MarketsPanel` (passed
down to `TrendingDeck` as `deck`/`onDeckChange` instead of it owning a copy); the table's row order
is now `deckComparator(deck, ...)` applied to the full tab+search-filtered set (not just the top 6
the card row shows), with a caption echoing the active ranking method above the table.

**Test:** `npm run test:market-decks` (12/12) — each deck produces the correct order including the
"no data sinks to the bottom" and tie-break rules, and explicitly asserts the four decks produce
four genuinely different table orderings (the reported bug: the table no longer stays frozen).
